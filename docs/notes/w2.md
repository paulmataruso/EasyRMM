# W2 (Windows hardening apply and undo), notes for the integrator

Branch `ws/w2`, migration `90141_hardening_guard.sql` (renumber).

## Changelog lines

* Windows hardening can apply and undo the registry-valued settings of
  `autoplay`, `wdigest`, `anonymous`, `name-resolution`, `ntlm`, `uac`,
  `printing`, `winrm`, `rdp`, `smb` and `accounts` (ADR-0054, W2), by module
  or by setting ID (ADR-0078). Each value is read back and put back if wrong;
  undo restores what is still as EasyRMM left it.
* After an apply, the computer undoes the change itself unless the agent
  confirms within ten minutes (the connectivity guard).
* An apply or undo waits for any other hardening or software job on the same
  device.

## Implementation-status rows

* ADR-0054 W2: partly built. Registry-valued settings (36 of 128). Other
  kinds skipped with why. Daily check, harvest, restart-bound modules not
  built. Windows runner job written, not run.

## Privacy

Nothing leaves the computer. The server stores the setting IDs changed, the
value before and the time (job result), and one row per guard in
`hardening_guards`. The audit log records mode, modules, settings, tier,
agreement and guard minutes; the typed computer name is not stored.
