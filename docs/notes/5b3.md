# ADR-0055 slice 5b3: a name added to an IP install

Branch `ws/5b3`, based on the integration branch at `2c452995`.

## Built

* **`server/internal/tlsaddname`** (new): the added pair (console name and remote-access name).
  * `Preflight`: normalises both names, fills `mesh.<console>` when none is given, requires the same site (the remote-access name under the console's parent domain), resolves both and says whether an address is this server's. `Add` refuses a pair that does not point here.
  * `Add` (step-up in the API): one pair per install, IP installs only; records the row, starts a tlsmove move of both names to Let's Encrypt, asks every enrolled device seen in 30 days and inside `devscope.Allowed` to verify the authority's second certificate for each name (`tlstrust.Ask`, no authority added to trust: IP-enrolled agents already trust it); audit `tls.name_added`.
  * Reachability: the server fetches `https://<name>/.well-known/easyrmm-reach` (a per-process token) at most hourly, from a 5-minute tick; `BrowserConfirm` records a signed-in browser through the name. Reachable = either succeeded within 7 days. A warning opens (`tls:<console>`, through the existing `tlscert.Publisher`) when the fetch fails and no browser confirmed within 24 hours; it resolves at the next success.
  * States: `pending` -> `trusted` (both certificates held through tlsmove's acme source, and reachable) -> `untrusted` (a certificate gone, or no proof for the whole grace period). `OnTrust(console, mesh, trusted)` fires on each change and on Remove of a trusted pair.
  * `Remove`: cancels waiting moves, moves acme names back to `.env`'s source, drops the row, fires `OnTrust(false)`.
  * An in-memory cache (`Load`, kept by Add/Remove/Tick) answers `IsAdded`, `Trusted` and `SecondCertificate()` for the edge without a database read per handshake.
* **`pki.Authority.SecondCertificate(names)`**: a leaf for the added names only, signed by the authority, using the server key (a key pin held for the server stays valid), cached in memory, never in `SetAddresses`. The certificate every agent sees on the IP address does not change.
* **API** `tlsaddnameapi`: `GET/POST/DELETE /api/v1/settings/certificates/added-name`, `POST .../check`, `POST .../resend` (settings.manage; add and remove need step-up), `POST .../browser-confirm` (any session; uses the request Host), and unauthenticated `GET /.well-known/easyrmm-reach`.
* **Edge**: `moveCerts.route` serves an added name from its Let's Encrypt certificate only while the pair is trusted and the certificate is valid, and from the authority's second certificate otherwise.
* **Console**: `AddedName` card on Settings > Certificates: name form with the remote-access name filled in, "Check the names", "Agree and get certificates", progress (certificates in hand, reachability evidence, agents that verified), "Ask agents again", "Remove name". Posts a browser confirmation when the console is loaded through an added name.
* **Migration** `90630_tls_added_names.sql`: one-row table (unique index on `(true)`), platform table like `tls_names`.

## Left for the integrator

1. **IP installs have no certificate service.** `d.TLS` (tlscert) exists only in `acme` mode, and `acme` is refused for an IP `EASYRMM_PUBLIC_URL`. Until the certificate service is also built for an IP install in `internal` mode (with its HTTP-01/TLS-ALPN-01 routing, which 5b2's "challenges in internal and manual modes" should provide), `Add` returns `unavailable` there. The code path is complete behind `Deps.Held` and `moveCerts.tls`; wiring is in `app/tlsadd.go`.
2. **Components table not wired.** `OnTrust` only logs in `app/tlsadd.go`. The ADR's origins, CSRF/CSP, MeshCentral `allowedOrigin`/`allowedFramingOrigins` (needs the separate fix), install commands, email links, authenticator issuer and WebAuthn follow it; each needs a hook off `TLSAdd.Trusted`/`OnTrust`.
3. **No remove-at-expiry of Let's Encrypt for an added name** beyond the grace rule: the edge falls back to the second certificate whenever the Let's Encrypt one is not served or not valid.
4. The agent ask uses purpose `target`, host = the name; tlsmove's own completion clears `target` rows for that host, so the "agents verified" counts reset when the move completes. A distinct purpose would keep them (needs a CHECK change on `device_tls_trust`).
5. Renumber the migration; add `tls_added_names` to `database.md`; mount `GET /.well-known/easyrmm-reach` on every origin (it is on the API mux); `docs` for the new audit actions (`tls.name_added`, `tls.name_trusted`, `tls.name_untrusted`, `tls.name_removed`).
6. The daily "same fetch again" runs hourly-capped from a 5-minute tick; no schedule beyond that. ADR's "by the operator's browser from the page" for DNS-01 is 5b4.
