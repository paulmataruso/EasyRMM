# Notes for slice C3 (ADR-0078, about 15 new endpoint checks), for the integrator

## Changelog lines

- Compliance checks (ADR-0078 C3): 23 new Windows checks in seven new hardening modules (sign-in notice, inactivity lock, password reveal,
  FIPS mode, removable disks, Windows Script Host, user rights, local administrators, time service and synchronization,
  application control, Office macros) and two Remote Desktop session limits, plus an SSH session limit and an account lockout
  check on Linux. Each is a library control mapped to NIST SP 800-171 and CMMC requirements. Those with a registry setting can be applied and undone.

## For the integrator

- No migration. Controls are content (`server/internal/compliance/content`); `packlint -update` was run.
- Hotspots, additive: module lists in `windows_hardening.go`, `hardening.go`, `windows_hardening_change.go` (tiers), `library.go`, `windowsText.ts`,
  `hardeningText.ts`, the profiles and the 800-171 and CMMC L2 mappings. `windows.ps1` keeps CRLF (`.gitattributes`).
- `windows.ps1`: `Test-ErDeviceGuard` now reads Device Guard through the new `Get-ErDeviceGuard` (same cache, same result).
- Job names: a scan that asks for many modules now names its job by their number (`moduleList`), because the jobs table limits a name to 200 characters.
- `testdata/windows-hardening-check.txt` has the seven new modules added by hand; it has not been re-recorded on a real Windows.
- Dev scope: no new automatic behaviour (checks run only when a scan or a person asks, through C1's guarded scan).
- The new Windows test `TestWindowsC3ChecksAsSystem` runs under the existing "Windows hardening as LocalSystem" job.

## Privacy notes

- User rights results report counts and the words "only those" or "N other account(s)", never account names or SIDs. The local administrators check reports
  a count. No new personal data leaves a computer. The time check records the age of the last synchronization.
