# Implementation status

Statuses:

* **Not started**
* **In progress** — work has begun.
* **Implemented** — code exists, but tests or other layers are missing.
* **Tested** — automated tests cover the behavior, but not every layer is
  done (e.g. backend only, no UI).
* **Complete** — backend, frontend, permissions, error handling and tests all
  exist.

A visible interface alone never counts as Implemented.

Last updated: 2026-11-16.

| Feature | Status |
|---|---|
| EasyPatch changes | Not needed for the connector: EasyPatch 1.9.0's API tokens replace the planned integration credentials (ADR-0030). | Connector and native patch UI | Complete against EasyPatch 1.9.0. ADR-0030. **Settings → EasyPatch**: server, API token (sealed), CA, checks; organizations linked by hand; devices linked by what the EasyRMM agent reads from the local EasyPatch agent (`status --json`), verified against EasyPatch (server, organization, active endpoint, credential fingerprint, host name, serial, one device per endpoint) with the reason when refused. **Patching** in the main menu: devices with compliance, missing, failed and exploited updates, last scan and restarts, filtered by organization, site, device group, status and name; bulk scan and install; EasyPatch jobs with progress, items and events, and cancel. Verified: client unit tests, PostgreSQL integration tests (links, every refusal reason, roles, actions, audit) and an HTTP API test against an in-process EasyPatch with 1.9.0's recorded answers, console tests, and on the preview against a real EasyPatch 1.9.0 server and its Linux agent: a wrong token refused, an Operator token connected, the organization linked and the device linked to its endpoint within seconds, the fleet and device views, a scan started (and a second one refused by EasyPatch as a duplicate, listed as not started), a job cancelled, all audited; and on a Debian 13 test machine running systemd, whose EasyPatch agent EasyRMM installed (below): the first scan listed a missing security update, **Install updates** from the device's Patches tab installed it (EasyPatch job completed, 1 of 1 installed, the package at the new version on the machine), and the device showed up to date after the next scan, audited. **Not yet verified against EasyPatch**: scheduled installs (no released EasyPatch has the capability), Windows endpoints |
| EasyPatch agent installed by EasyRMM | Complete for Linux; built for Windows, not yet run there. ADR-0031. **Install EasyPatch agent** on chosen devices with no EasyPatch agent (Patching, or the device's Patches tab, `patch.manage`), or **Install automatically** per linked organization (Settings → EasyPatch, `settings.manage`; failed automatic installs retried hourly, three times). The server signs an instruction into the agent's heartbeat (job key, own signature context, bound to the device, 15 minutes) with EasyPatch's address and CA, the newest package for the device and a single-use, one-hour enrollment token for the linked organization (site matched by name), never stored and revoked on failure. The agent checks again that no EasyPatch agent is present, downloads the package, verifies its size and SHA-256, installs it (msiexec; apt-get or dnf with systemd) and enrolls it, one install at a time within 20 minutes; agent updates wait for it. The console shows each install's state and the reason it failed. Audited. Verified: unit tests (signing and every check, the installer with a fake system, Linux with stand-in apt-get, dnf and enroll programs, downloads over TLS), PostgreSQL integration tests (requests, roles, eligibility, heartbeats, preparation failures, timeouts, automatic installs and retries, token revocation), an HTTP API test, console tests, and on the preview against a real EasyPatch 1.9.0: a device without systemd failed with that reason and its token was revoked; on a Debian 13 machine with systemd (installed with the console's own install command), the EasyPatch agent was downloaded, installed with apt-get and enrolled within 12 seconds of the instruction, and the device linked to its new endpoint four minutes after the request. **Not yet verified**: the Windows installer path (msiexec, `SERVERCACERT`, enroll) on Windows, dnf/rpm on a real machine, arm64, and automatic installs on the preview (its only linked organization holds real Windows machines) |
